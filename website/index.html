THE SHORTEST SUCCESSFUL PATH

Four checks before tuning

  1. 01
    Check the inputs

    One LiDAR stream with per-point time, one 6-axis IMU, a LiDAR-to-IMU transform, and timestamps on the same clock.

  2. 02
    Choose the closest profile

    Start from the rig calibration in cfg/. Change sensor values first, not algorithm defaults.

  3. 03
    Start stationary, then launch

    Keep the platform still for initialization, then run the ROS wrapper live or replay a bag with simulated time enabled.

  4. 04
    Inspect the output

    Check odometry, trajectory, and map in RViz. Exit normally to write the TUM file.

03 Why Sapphire

Keep setup simple.
Know what the result means.

Getting a LiDAR-inertial system to launch is only half the problem. Sensor timing, frames, calibration, and motion all affect whether the map is usable. Sapphire is organized to make those assumptions visible and the first result easier to validate.

START SIMPLER

Profiles, not a blank page

Begin with a working configuration for a known sensor rig. Keep calibration, timing, noise, and registration assumptions in one file instead of discovering them through repeated trial and error.

MOVE CONSISTENTLY

One model for the whole scan

IMU propagation and scan deskew share one Gal(3) motion model. Motion prediction and point correction use the same account of how the platform moved while the scan was collected.

TRUST THE RESULT

Benchmarks without a cover-up

See performance across four public dataset families, including incomplete and invalid runs. Metrics are labeled clearly so you can judge where the current system is useful and where it is not.

04 How it works

From timed scans
to a usable map.

Once data starts arriving, Sapphire handles the moving parts for you: time-aware motion correction, scan registration, state update, and optional pose-graph correction. The technical details stay available when you need them.

01 / INPUT

Receive LiDAR + IMU

Timed point clouds and inertial measurements enter through ROS or your own C++ data source.

02 / CORRECT

Remove motion distortion

Each scan is corrected using the estimated platform motion during its acquisition.

03 / ALIGN

Estimate the pose

The scan is aligned to a local submap and fused with IMU state to produce continuous odometry.

04 / OUTPUT

Publish trajectory + map

Use live ROS topics for navigation and visualisation, or save a TUM trajectory for analysis.

INSIDE THE CORE

Each stage has one job

The ROS wrappers only translate messages, frames, timing, and profiles. The estimator remains a standalone C++17 library.

Inspect the pipeline API
01

Stationary initialization

IMU

Estimate gyro and accelerometer bias, then align gravity.

02

Gal(3) motion

SHARED

Deskew the scan and propagate the state with one preintegration model.

03

Local registration

VGICP / GICP

Align against a voxelized local submap with explicit accept and reject gates.

04

State fusion

ESKF / OBSERVER

Turn the registration residual into a pose, velocity, and bias update.

05

Asynchronous pose graph

ISAM2

Optimize keyframes beside the frontend and apply map corrections.
