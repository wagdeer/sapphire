# 独立里程计与滑窗建图拆分：后续架构试验

状态：**用户明确要求安排，待本轮内存/SIMD验收形成基线后尝试；尚未实现。**

## 产品意图

实时 LiDAR/IMU odometry 优先保证连续跟踪，拥有独立局部匹配地图、状态与质量输出。现有高精度滑窗 LiDAR/IMU 优化下沉到 mapping，负责局部几何精化和 submap 生成。建图平面质量不足、窗口拒收或优化失败，不应直接触发 odometry reset；真实前端失效必须显式报告，不能把纯惯性预测冒充有效定位。视觉继续只做关键帧选择、历史召回与回环初值，不成为视觉里程计。

## 当前耦合证据

pipeline.cpp::update_lidar_window 的 ESKF 匹配使用同一 voxel_map_，随后向同一地图添加滑窗观测；窗口优化结果回写 current_state_。update_lidar_window 的拒绝积累触发 system_reset，清空地图/窗口，并通知 mapping 重置。所以“ESKF已在BA前面”并不表示已经有独立 odometry。

Hilti max_layer1（1m根/0.5m最小）仅改一个算法参数的历史完整回放出现13次Reset、进程退出码1；原max_layer2没有该现象。2026-10-08当前代码离线插桩对照（保留局部BA，关闭视觉/全局位姿图）进一步定位：max_layer1的51次观测拒绝均触及法向最小特征值<14，累计造成2次跟踪重置；随后28次初始化失败中5次平面因子不足10，23次最后记录的法向最小特征值<15，部分还同时违反重力模长范围。max_layer2为0拒绝/0重置，输出与此前ESKF基线逐项一致。当前30次与历史13次不是同一次实验；旧日志没有分支信息，不能反推其精确组成。证据说明平面表示、固定计数门限及重初始化策略耦合，不足以证明门限误杀或放宽后精度合格。诊断使用已有特征值门限，不新增按退化方向控制；后续优先验证用户提出的GICP类观测兜底。[复现与逐帧证据](../../audit/2026-10-07-voxel-reset/PLAN.md)。

## 试验边界

1. 前端独立消费IMU/LiDAR，输出原始odom域连续位姿、时间和质量；自身局部地图有显式容量/范围规则。前端几何模型与关联策略通过退化数据决定，不默认复制高精度建图平面筛选。
2. mapping通过有界队列取得观测与只读原始odom先验。现有窗口优化作为局部建图精化；拒收/延迟可降低建图产出，不回写前端估计或重置其owner。
3. 原始 T_odom_body 与精化 T_submap_body 必须区分。选定submap锚点、观测冻结、相机位姿解释、协方差/信息传递和跨窗口边契约后再实施；不得拿优化位姿重解释已有历史观测。
4. 后端负责submap关联、图优化和revision提交。既有A1–B3/A2/F1关闭状态不重开；新生产者必须适配已有W提交边界，不能用solver临时态替代committed layout。
5. 不通过复制完整点云地图造成双份无界缓存；梳理点云/点簇跨线程所有权、共享不可变数据、销毁时点与总内存预算。是否采用ICE-BA式增量计算/相对先验需独立数值设计，不等同于本次线程或缓存拆分。

## 对照验收

先锁定现有0.25m、360x270/500特征、SIMD/两线程/packed-double版本。再做可独立开关的最小拆分试验，覆盖Hilti和更长/退化数据：实时odom中断/Reset/预测-only占比、建图拒收与排队、在线/子图/committed轨迹误差、在线回环、CPU/p95/p99/RSS<1,000,000,000B，以及停止/恢复/落库的生产边界。

必须验证两条独立性质：mapping退化不拉垮可用的odom；odom失效不会被mapping成功状态遮蔽。0.5m可作为拆分后的压力对照，不能靠扩大体素并放宽平面门槛直接宣布解决。
