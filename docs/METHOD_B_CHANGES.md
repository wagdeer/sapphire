# Method B 独立版变更说明

## 独立构建和运行

提交 `1982d46` 将 `method_b` 整理为只构建和运行 Method B 的分支。从 CMake 目标、运行入口和配置中移除了原来并存的 main 专属管线。应用统一使用 `sapphire::OdometryPipeline`，配置位于 `cfg/cfg_b/`。与 `main` 做 A/B 时，各自检出并编译两个分支，使用相同输入回放。

## 滑窗优化器

体素因子只保留实际有观测的帧，缓存 IMU 预积分的信息矩阵，复用已接受状态的平面特征值和残差。拒绝试探步长时恢复接受状态的缓存。该改动减少了空块计算、重复求逆和重复特征分解，保留原有收敛策略。

## 配置和建图分支

参数按输入输出、传感器、里程计、子图与 BA、PGO 和回环查询分组。激光入口裁剪与子图打包裁剪分别控制原始回波和后端几何。近期地图反馈和反馈前 BA 分别配置，封图 BA 独立执行。对外地图和轨迹始终做重力对齐。

在线子图等到关键帧数和有效平面体素数都达标才封存。结束回放时封存剩余尾段。刚性压缩仍根据几何约束及边界形变判断，超限时保留逐帧位姿与里程计约束。

## 地图哈希顺序

体素表调用 `clear()` 后仍保留上一个子图的桶容量。相同输入接在不同子图之后时，可能以不同的顺序归档。顺序变化可影响后续配准的近邻索引和浮点累加。

新子图从独立的空哈希表开始，由后端拥有的内存池复用小节点分配。大桶数组由上游分配器管理，内存池随子图后端析构。回归测试对比单独建图和接在较大子图之后建图，要求两个子图的体素顺序一致。

## iESKF 协方差数值修复

观测更新末尾直接把 `0.5 * (P + P.transpose())` 赋给 `P`。写入一侧时，后续计算可能从转置视图读到已经覆盖的系数，使后验协方差的上下三角不一致。修复先计算完整的对称矩阵，再写回协方差。回归测试通过真实的观测更新入口，检查后验协方差严格对称。

固定交付的 NCLT 诊断使用同一可执行文件，只切换协方差算式，并交换 CPU 核组。旧算式六轮中有一轮复现第 4,491 帧的分叉。修复算式六轮的 5,286 个原始位姿逐帧一致。

## 验证入口

- `sapphire_submap_test` 检查几何达标封图、尾段收尾和体素归档顺序。
- `sapphire_registration_test` 检查 IMU 噪声参数、后验协方差与历史回访。
- [数据集回放说明](DATASET_REPLAY.md) 说明独立构建、传感器配置和实采回放。
