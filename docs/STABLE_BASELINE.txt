Sapphire 收敛基线 — 2026-11-02

范围
固定现有算法主线，不为 Dormitory alpha 或其他单个困难片段增加逻辑。
前端 ESKF + 滚动 LiDAR/IMU BA；reset 后继续初始化；有效片段保存；后端以
压缩局部 batch 为最小图节点，异步几何重定位和常规 PGO。验证状态见文末。
不恢复长期贝叶斯/粒子假设库，不采用 ESKF-only、10 秒切块或 KD-tree 试验。

前端所有权与冻结
FrontendRuntime 单线程持有实时状态和 LocalMap。默认 10 帧窗口保留帧身份、
体坐标点云及 IMU 连接，进行原有局部 BA。初始化仍复用 KD-tree 观测和重力 BA。
沿用原 BA 位姿回馈契约，本次不引入未经验证的速度/偏置/协方差融合模型。
lidar_update 是 BA 前诊断；odom_state 和当前帧点云在 BA 接受后一起发布。
不要把诊断轨迹与 BA 后轨迹混作同一种评估输出。

每次满窗优化后，只退休最老一帧的几何证据。以其最终局部位姿变换 Gaussian
统计量，移交一次；保留的帧继续参加 BA。固定历史缓存的淘汰不删除已归档
证据，也不能淘汰仍参与 BA 的活动观测。64 MiB 是固定缓存预算，不是总 RSS。
保留纯因子求值：试探位姿不修改地图，边缘化从接受状态重新计算。
删除未被消费的 LidarFrame 方差字段；后端沿用明确配置的里程计噪声。

batch / 图节点
BackendRuntime 持有现有 NodeBuilder，将连续退休证据变换到 batch 首帧坐标系，
合并相同来源体素的 Gaussian 统计量，保留各观测的轨迹锚定关系。
冻结帧是内部交接粒度，batch Node 才是持久化、重定位和 PGO 的几何单元。
不把相邻重叠 BA 窗口的整份地图重复交给后端。
沿用现有 15 m 行程切分、256 帧历史界限和几何载荷上限；reset/EOF 封存短尾。
这些是既有分块/资源策略，本次不宣称最优尺寸，也不重新改成固定秒数。

reset / session
数据异常、不可用、断流和连续观测拒绝走同一恢复状态机。取消未接受输入，
封存可用旧窗口及不足一个 batch 的尾段，清理估计器并重新初始化。
非有限估计失败不把已污染活动状态当作有效地图保存；已冻结证据仍保留。
generation 有序界定新旧坐标原点；一个 batch 不能跨 reset。同 session 的
连续 batch 建里程计边，不向无连接的新 session 编造里程计跨段边。
所有有效片段共用持久归档、保持独立原点；不匹配也照常落盘。

后台重定位与 PGO
前端、后端所有者、几何配准任务各自独立；配准不占用前端调用栈，不回写
前端状态。保留有界 FIFO 和存储背压，不承诺无限慢存储下仍然无等待。
后台至多一个几何任务，只持有冻结几何及必要坐标元数据；忙时继续保存节点。
结果由后端所有者检查几何版本/图关系，再试解 PGO、提交图及坐标修正。

同 session 的基础空间候选和跨 session 的全局几何检索共享重定位验证与提交。
已有共同坐标系才可使用图位姿初值；未知原点用现有 G3Reg/PAGOR 初始化。
共同消费 Gaussian 子图，统一 GICP、单次查询歧义判断；证据不足就不连接。
后端可选 BA、Gaussian 融合和历史匹配窗口策略已移除，冻结 batch 保持不变。
相关旧配置项明确报错，不静默接受无效开关。前端滚动 BA 始终保留。
PGO 改变 batch 位姿及全局坐标修正，不修改已归档 batch 内部几何或前端状态。

稳定性含义及验证
这是架构和默认算法分支的收敛，不是所有场景定位成功、已解决全部 BA 精度
问题或已满足 Orin NX 实时预算的声明。reset 只能响应已有健康检测，不能保证
识别所有有限数值但错误的轨迹。Dormitory 专项反例保留，暂不继续调参或修补。
本轮代码、测试及真实输入结果记录在
BASELINE_VALIDATION.txt。
验收关注滚动 BA、观测一次性冻结、reset/尾段、跨进程归档恢复、异步重定位和
PGO，以及不同真实数据短程运行；不以某一段重新拼上作为验收条件。
